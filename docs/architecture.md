# Архітектура продукту

## 1. Загальний опис

Dress Rental Planner — навчальний продукт для студії оренди одягу.

Його мета — допомогти власнику або працівнику студії контролювати замовлення, дати оренди, відправлення, повернення речей та склад кожного замовлення.

На поточному етапі проєкт також містить Telegram-бота на aiogram.

## 2. Frontend

Frontend — це частина продукту, з якою взаємодіє користувач.

У моєму проєкті роль frontend виконує Telegram.

Користувач бачить:
- повідомлення бота;
- команди /start та /help;
- кнопку Help;
- відповіді на свої дії.

Telegram передає дії користувача до backend частини бота.

## 3. Backend

Backend — це логіка продукту, яка обробляє запити користувача.

У моєму проєкті backend написаний на Python з використанням aiogram.

Файл:

app/main.py

Backend:
- отримує команди від Telegram;
- визначає, яку функцію потрібно виконати;
- формує відповідь;
- записує інформацію в logs;
- у майбутньому може працювати із замовленнями та базою даних.

Наприклад, після команди /start функція start_handler() отримує повідомлення і відправляє користувачу відповідь.

## 4. Database

Database — це місце, де продукт зберігає дані.

Зараз окрема база даних у проєкті ще не підключена.

У майбутньому база даних Dress Rental Planner може зберігати:
- клієнтів;
- замовлення;
- речі;
- дати оренди;
- дати відправлення;
- дати повернення;
- статуси замовлень.

Наприклад, для цього можна використовувати PostgreSQL.

## 5. API

API дозволяє різним частинам системи обмінюватися даними.

У моєму проєкті Telegram Bot API забезпечує зв'язок між Telegram та моїм Python-ботом.

Схема роботи:

Користувач → Telegram → Telegram Bot API → aiogram backend → відповідь → Telegram → користувач

У майбутньому власний API може використовуватися між frontend Dress Rental Planner, backend та database.

## 6. Приклад роботи системи

Користувач натискає /start.

1. Telegram отримує команду.
2. Telegram Bot API передає її боту.
3. aiogram знаходить функцію start_handler().
4. Backend виконує функцію.
5. Бот відправляє відповідь.
6. Telegram показує відповідь користувачу.

## 7. Приклади функцій у реальних застосунках

### Функція 1 — створення замовлення

У Dress Rental Planner користувач може створити нове замовлення.

Frontend:
форма або Telegram-команда для введення даних.

Backend:
перевіряє дані та створює замовлення.

Database:
зберігає інформацію про замовлення.

API:
передає дані між frontend і backend.

### Функція 2 — перегляд замовлень на сьогодні

Frontend:
користувач натискає кнопку або команду.

Backend:
визначає поточну дату та шукає потрібні замовлення.

Database:
повертає замовлення на сьогодні.

Frontend:
показує список користувачу.

### Функція 3 — зміна статусу замовлення

Наприклад:
"Підготовка", "Відправлено", "В оренді", "Повернуто".

Frontend:
користувач обирає новий статус.

Backend:
перевіряє зміну.

Database:
оновлює статус замовлення.

### Функція 4 — нагадування про відправлення

Backend перевіряє дати майбутніх замовлень.

Якщо замовлення потрібно відправити сьогодні, система формує нагадування.

Telegram Bot API може доставити це повідомлення користувачу.

### Функція 5 — пошук клієнта

Frontend:
користувач вводить ім'я або телефон клієнта.

Backend:
обробляє пошуковий запит.

Database:
знаходить відповідні записи.

Frontend:
показує знайденого клієнта та його замовлення.
