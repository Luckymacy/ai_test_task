# AI Prompt Optimization Notes

## Мета

Мета завдання — покращити якість AI-аналізу фінансових операцій у Dress Rental Planner, зробити prompt більш структурованим і передбачуваним, а також порівняти обсяг вхідних даних у форматі raw JSON та короткого зведення.

---

## 1. Weak Prompt

Слабкий prompt:

Проаналізуй фінансові операції студії оренди одягу.

Операції:
{transactions_json}

Поверни короткий аналіз:
- підсумок;
- основні категорії витрат;
- ризики;
- рекомендації.

### Недоліки weak prompt

- нечітко задана роль моделі;
- немає вимоги повертати валідний JSON;
- немає чіткої структури відповіді;
- модель може додавати Markdown або довільний текст;
- немає заборони вигадувати дані;
- не визначено, як поводитися при недостатній кількості даних;
- результат складніше стабільно використовувати у frontend.

---

## 2. Improved Prompt

Покращений prompt:

Ти фінансовий AI-аналітик невеликої студії оренди одягу The Muse Edit.

Проаналізуй тільки наведені фінансові операції.
Не вигадуй дані, яких немає у вхідних даних.

Поверни тільки валідний JSON без Markdown і додаткового тексту.

Структура відповіді:

{
  "summary": "короткий підсумок фінансової ситуації",
  "top_expense_categories": [
    "категорія 1",
    "категорія 2"
  ],
  "risks": [
    "ризик 1",
    "ризик 2"
  ],
  "advice": [
    "порада 1",
    "порада 2"
  ]
}

### Переваги improved prompt

- чітко визначена роль AI;
- задана конкретна бізнес-сфера;
- відповідь має стабільну структуру;
- JSON можна напряму використовувати у React;
- знижено ризик вигаданих даних;
- визначена мова відповіді;
- рекомендації не повинні дублюватися;
- модель має вказувати на недостатність даних, якщо це потрібно.

---

## 3. Сценарій 1 — Переважно доходи

Приклад операцій:

[
  {
    "type": "income",
    "amount": 1800,
    "category": "rental",
    "description": "Оренда сукні"
  },
  {
    "type": "income",
    "amount": 1600,
    "category": "rental",
    "description": "Оренда костюма"
  },
  {
    "type": "expense",
    "amount": 200,
    "category": "cleaning",
    "description": "Хімчистка"
  }
]

### Очікувана поведінка AI

AI повинен визначити, що:
- доходи перевищують витрати;
- основна категорія доходу — rental;
- витрати є відносно невеликими;
- ризик може бути пов'язаний із залежністю від одного типу доходу;
- рекомендації мають базуватися лише на переданих операціях.

- існує ризик низької маржинальності або від'ємного балансу;

## 5. Сценарій 3 — Недостатньо даних

Приклад операцій:

[
  {
    "type": "income",
    "amount": 500,
    "category": "rental",
    "description": "Оренда сукні"
  }
]

### Очікувана поведінка AI

AI повинен:
- не робити категоричних висновків про фінансовий стан;
- прямо вказати, що даних недостатньо для повноцінного аналізу;
- не вигадувати витрати, категорії або ризики, яких немає у вхідних даних;
- формулювати рекомендації обережно;
- базувати відповідь тільки на наявній операції.

Цей сценарій важливий для перевірки того, що improved prompt зменшує ризик hallucination і не змушує модель заповнювати відсутні дані вигаданими висновками.

## 6. Weak vs Improved — результат тестування

Weak prompt дає менш передбачуваний результат.

Основні проблеми:
- формат відповіді може змінюватися між запитами;
- модель може повертати звичайний текст замість JSON;
- можуть з'являтися додаткові пояснення поза потрібною структурою;
- складніше автоматично обробляти відповідь у frontend;
- вища ймовірність отримати припущення, які прямо не підтверджуються вхідними даними.

Improved prompt дає більш контрольований результат.

Основні переваги:
- відповідь повертається у стабільній JSON-структурі;
- чітко визначені поля summary, top_expense_categories, risks та advice;
- модель отримує заборону вигадувати відсутні дані;
- задана українська мова відповіді;
- відповідь простіше напряму відображати у React;
- легше перевіряти коректність відповіді на backend;
- модель краще поводиться при недостатній кількості даних.

Для SaaS-застосунку improved prompt є надійнішим, оскільки frontend очікує передбачуваний формат відповіді.

## 7. Raw JSON vs Summary

### Raw JSON

При передачі всіх операцій у сирому вигляді модель отримує:
- дату;
- тип операції;
- суму;
- категорію;
- опис кожної операції.

Переваги:
- AI бачить максимум деталей;
- можна аналізувати окремі операції;
- менший ризик втрати контексту;
- можна знаходити проблеми у конкретних транзакціях.

Недоліки:
- більше input tokens;
- вища вартість API;
- зі збільшенням кількості операцій prompt стає довшим;
- менш ефективне масштабування при великій історії транзакцій.

### Summary

Замість raw JSON backend може попередньо сформувати коротке фінансове зведення.

Приклад:

{
  "total_income": 3400,
  "total_expenses": 200,
  "balance": 3200,
  "expense_categories": {
    "cleaning": 200
  }
}

Переваги:
- менше input tokens;
- нижча вартість API;
- швидший аналіз;
- prompt залишається компактним навіть при великій кількості операцій;
- зручно для загального фінансового аналізу.

Недоліки:
- AI не бачить деталей кожної операції;
- частина контексту може бути втрачена;
- складніше аналізувати конкретні транзакції.

---

## 8. Token Comparison

Для порівняння було використано однаковий набір фінансових даних у двох форматах:

- raw JSON з повними даними по кожній операції;
- summary з агрегованими фінансовими показниками.

Підрахунок було виконано окремим скриптом token_compare.py.

Результат:

- RAW JSON: 117 tokens
- SUMMARY: 44 tokens
- Різниця: 73 tokens
- Економія: 62.4%

Отже, у цьому прикладі використання summary дозволяє зменшити кількість input tokens приблизно на 62.4%.

При збільшенні кількості транзакцій різниця може ставати ще більш суттєвою, оскільки raw JSON збільшується разом із кожною новою операцією, а summary може залишатися відносно компактним.

Попереднє агрегування даних на backend може зменшити:
- кількість input tokens;
- вартість API-запитів;
- розмір prompt;
- час обробки запиту.

Raw JSON доцільно використовувати тоді, коли AI повинен аналізувати конкретні транзакції та їх деталі.

Summary є більш ефективним для загального фінансового аналізу, коли достатньо агрегованих показників.

---

## 9. Висновок

Improved prompt є кращим варіантом для Dress Rental Planner, оскільки забезпечує більш стабільну, контрольовану та структуровану відповідь.

Основні покращення:
- чітка роль AI;
- конкретний бізнес-контекст;
- контроль формату відповіді;
- стабільний JSON;
- заборона вигадування даних;
- визначена мова відповіді;
- контроль ризиків і рекомендацій;
- передбачувана інтеграція з React;
- коректніша поведінка при недостатній кількості даних.

Для невеликої кількості операцій можна передавати raw JSON, оскільки він містить більше деталей.

Для великої історії транзакцій доцільно агрегувати дані на backend та передавати AI summary. У проведеному тесті summary потребував 44 tokens замість 117 tokens для raw JSON, що дало економію приблизно 62.4%.

Таким чином, оптимізація prompt стосується не лише якості текстової інструкції, а й оптимізації самих вхідних даних. Це дозволяє зробити AI-функціонал більш передбачуваним, дешевшим і придатним до масштабування.
