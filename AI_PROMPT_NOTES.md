# AI Prompt Optimization Notes

## Мета

Мета завдання — покращити якість AI-аналізу фінансових операцій у Dress Rental Planner, зробити prompt більш структурованим і передбачуваним, а також порівняти обсяг вхідних даних у форматі raw JSON та короткого зведення.

---

## 1. Weak Prompt

Слабкий prompt:

Проаналізуй фінансові операції студії оренди одягу.

Операції:
{transactions_json}

Поверни короткий аналіз:
- підсумок;
- основні категорії витрат;
- ризики;
- рекомендації.

### Недоліки weak prompt

- нечітко задана роль моделі;
- немає вимоги повертати валідний JSON;
- немає чіткої структури відповіді;
- модель може додавати Markdown або довільний текст;
- немає заборони вигадувати дані;
- не визначено, як поводитися при недостатній кількості даних;
- результат складніше стабільно використовувати у frontend.

---

## 2. Improved Prompt

Покращений prompt:

Ти фінансовий AI-аналітик невеликої студії оренди одягу The Muse Edit.

Проаналізуй тільки наведені фінансові операції.
Не вигадуй дані, яких немає у вхідних даних.

Поверни тільки валідний JSON без Markdown і додаткового тексту.

Структура відповіді:

{
  "summary": "короткий підсумок фінансової ситуації",
  "top_expense_categories": [
    "категорія 1",
    "категорія 2"
  ],
  "risks": [
    "ризик 1",
    "ризик 2"
  ],
  "advice": [
    "порада 1",
    "порада 2"
  ]
}

### Переваги improved prompt

- чітко визначена роль AI;
- задана конкретна бізнес-сфера;
- відповідь має стабільну структуру;
- JSON можна напряму використовувати у React;
- знижено ризик вигаданих даних;
- визначена мова відповіді;
- рекомендації не повинні дублюватися;
- модель має вказувати на недостатність даних, якщо це потрібно.

---

## 3. Сценарій 1 — Переважно доходи

Приклад операцій:

[
  {
    "type": "income",
    "amount": 1800,
    "category": "rental",
    "description": "Оренда сукні"
  },
  {
    "type": "income",
    "amount": 1600,
    "category": "rental",
    "description": "Оренда костюма"
  },
  {
    "type": "expense",
    "amount": 200,
    "category": "cleaning",
    "description": "Хімчистка"
  }
]

### Очікувана поведінка AI

AI повинен визначити, що:
- доходи перевищують витрати;
- основна категорія доходу — rental;
- витрати є відносно невеликими;
- ризик може бути пов'язаний із залежністю від одного типу доходу;
- рекомендації мають базуватися лише на переданих операціях.

## 5. Raw JSON vs Summary

### Raw JSON

При передачі всіх операцій у сирому вигляді модель отримує:
- дату;
- тип операції;
- суму;
- категорію;
- опис кожної операції.

Переваги:
- AI бачить максимум деталей;
- можна аналізувати окремі операції;
- менший ризик втрати контексту.

Недоліки:
- більше input tokens;
- вища вартість API;
- зі збільшенням кількості операцій prompt стає довшим.

### Summary

Замість raw JSON backend може попередньо сформувати коротке фінансове зведення.

Приклад:

{
  "total_income": 5200,
  "total_expenses": 1700,
  "balance": 3500,
  "expense_categories": {
    "cleaning": 700,
    "advertising": 600,
    "repair": 400
  }
}

Переваги:
- менше input tokens;
- нижча вартість API;
- швидший аналіз;
- prompt залишається компактним навіть при великій кількості операцій.

Недоліки:
- AI не бачить деталей кожної операції;
- частина контексту може бути втрачена;
- складніше знаходити проблеми в окремих транзакціях.

## 6. Token Comparison

Для порівняння було використано однаковий набір фінансових даних у двох форматах:

- raw JSON з повними даними по кожній операції;
- summary з агрегованими фінансовими показниками.

Результат підрахунку токенів:

- RAW JSON: 117 tokens
- SUMMARY: 44 tokens
- Різниця: 73 tokens
- Економія: 62.4%

Отже, у цьому прикладі використання summary дозволяє зменшити кількість input tokens приблизно на 62.4%.

Це означає, що при великій кількості фінансових операцій попереднє агрегування даних на backend може суттєво зменшити:
- кількість input tokens;
- вартість API-запитів;
- розмір prompt;
- час обробки запиту.

Raw JSON доцільно використовувати тоді, коли AI повинен аналізувати конкретні транзакції та їх деталі.

Summary є більш ефективним для загального фінансового аналізу, коли достатньо агрегованих показників.

---

## 7. Висновок

Improved prompt є кращим для SaaS-застосунку, оскільки він забезпечує більш стабільну та структуровану відповідь.

Основні покращення:
- чітка роль AI;
- контроль формату відповіді;
- стабільний JSON;
- заборона вигадування даних;
- визначена мова відповіді;
- контроль ризиків і рекомендацій;
- зручна інтеграція з React.

Для великої кількості фінансових операцій доцільно використовувати попереднє агрегування даних на backend і передавати AI summary замість повного raw JSON.

Raw JSON варто залишити для випадків, коли потрібен детальний аналіз окремих транзакцій.
